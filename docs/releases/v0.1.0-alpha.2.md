# Bubllio Core 0.1.0-alpha.2

This is an internal technical alpha for a controlled, single-installation
Dokploy rehearsal. It is not approved for real users, customer workloads, UAT,
or Production.

## What changed

- A release-generated, digest-pinned Dokploy Compose adapter can start Core
  without SSH, archive extraction, host files, or generated environment files.
- The operator supplies only `BUBLLIO_BASE_DOMAIN` and one unique
  `BUBLLIO_SETUP_SECRET` through the Dokploy service environment.
- A hardened one-shot initializer creates independent internal credentials in
  narrowly scoped named volumes and persists only the setup secret digest.
- Redeploying without the raw setup secret preserves credentials and data;
  changing initialized domain or setup authority fails closed.

## Install the alpha

Download `bubllio-core-0.1.0-alpha.2-dokploy.yaml` from this release and follow
the bundled [managed-platform guide](https://github.com/apodimi/bubllio-core/blob/v0.1.0-alpha.2/docs/deployment/managed-platforms.md).

Use a 43-character base64url setup secret generated from 32 random bytes. After
the browser setup claims the installation, delete the raw value from Dokploy
and redeploy.

## Known release gates

- A clean-host Dokploy rehearsal is still required before this adapter is
  described as validated.
- Trusted Dokploy/Docker administrators and platform history may see the raw
  setup value during bootstrap. This is an accepted internal-alpha risk, not a
  Production secret-delivery approval.
- The release is not cryptographically signed.
- Non-destructive recovery for a lost or expired setup secret remains open.
- SMTP provider approval, privacy and abuse controls, data lifecycle,
  backup/restore, monitoring, upgrade, rollback, complete member management,
  and CRM adoption remain open.
