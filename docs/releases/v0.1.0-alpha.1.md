# Bubllio Core 0.1.0-alpha.1

This is an internal technical alpha for a controlled, single-installation
rehearsal. It is not approved for real users, customer workloads, UAT, or
Production.

## Included

- the Core workspace and shared identity foundation;
- organization application availability and member app-grant foundations;
- a Docker-only, digest-pinned installation bundle;
- guided browser setup for system checks, email delivery, the first verified
  administrator, and the first organization; and
- the Docker Compose reference adapter with private database networks and no
  published application ports.

CRM does not consume the Core identity/access adapter yet. Board is not
implemented, and the complete member/grant administration experience remains
unfinished.

## Install the alpha

Download these release assets—not GitHub's automatic source archives:

- `bubllio-core-0.1.0-alpha.1.tar.gz`
- `bubllio-core-0.1.0-alpha.1.tar.gz.sha256`
- `release-manifest.json`

On a Linux host with Docker Engine and Docker Compose v2:

```bash
sha256sum --check bubllio-core-0.1.0-alpha.1.tar.gz.sha256
tar -xzf bubllio-core-0.1.0-alpha.1.tar.gz
cd bubllio-core-0.1.0-alpha.1

./bubllio prepare \
  --base-domain core.example.com \
  --edge-network proxy
./bubllio doctor
./bubllio up
```

Configure the HTTPS reverse proxy to route the derived hosts to the three public
targets on that network:

| Host                    | Target          |
| ----------------------- | --------------- |
| `core.example.com`      | `core-web:8080` |
| `api.core.example.com`  | `core-api:3100` |
| `auth.core.example.com` | `keycloak:8080` |

Then open `https://core.example.com/setup`. `prepare` prints the setup secret
once. Store it immediately; repeating preparation preserves credentials and
does not print the secret again.

## Known release gates

- The checksum detects corruption, but the release is not yet cryptographically
  signed and does not prove publisher authenticity by itself.
- A clean public-host rehearsal behind real DNS/TLS is still required.
- Non-destructive recovery for a lost or expired setup secret remains open.
- SMTP provider approval, abuse controls, privacy/legal decisions, data
  lifecycle, backups, restore, monitoring, upgrade, and rollback evidence remain
  open.
- Docker Compose is the tested reference adapter. A hosting panel or other
  platform is not production-certified merely because it can consume Compose.

See the bundled `README.md` and the repository
[deployment guide](https://github.com/apodimi/bubllio-core/blob/v0.1.0-alpha.1/docs/deployment/README.md)
for the complete operator and security boundaries.
